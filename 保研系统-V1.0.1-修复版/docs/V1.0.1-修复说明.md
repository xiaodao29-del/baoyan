## 二、按 PRD 13 章补齐的账号与会话规则

测试报告在 P2-4 / P2-5 引用了 PRD 13 章，本次一并落地：

- 密码 ≥8 位、须含字母与数字（`validate_password()`）
- 连续 5 次错误锁定 30 分钟（`MAX_LOGIN_FAILURES` / `LOCK_MINUTES`）
- 会话 30 分钟无操作自动失效（`PERMANENT_SESSION_LIFETIME` + `_seen_at` 空闲判断）
- 首次登录强制改密（`sys_user.must_change_pwd` 现在真正被读取）

`sys_user` 新增 `failed_attempts`、`locked_until` 两列；`schema.sql` 已同步，`db.py` 的 `ensure_schema()` 会在启动时给**已有数据库**自动补列——**不需要删库重跑 seed**，演示数据与 91.60 锚点不受影响。

## 三、顺手修掉的一个数据留痕问题

`admin_rules()` 原来在归档旧规则时，把旧记录的三项权重改写成新值再置 `ARCHIVED`，等于**历史版本被覆盖**，与 PRD 12 章「评分规则每次变更前后值对比」冲突。现在只改状态，权重原样保留，新值写入新版本行。

## 四、验证结果

用 Flask test client 直接打接口做本地自测（35 项断言全过；脚本未随包分发，避免改到演示库数据），覆盖：

- 无令牌 POST → 400；带令牌正常
- 初始密码登录 → 强制跳改密；弱口令（<8 位、纯字母）被拒；合规口令改完可正常访问，**91.60 锚点不变**
- `next=http://evil.example.com` / `next=//evil.example.com` → 都回落 `/home`；`next=/counselor/students` 正常回跳
- 绩点 4.625 → 存 4.63
- 排名传 9、作者排序传 8、日期传 `2026/13/45` → 均被拒并给出提示；合法数据（第 4 位、2026-05-20）正常落库
- 同一账号连错 5 次 → 第 5 次 429 且写入锁定时间；锁定期内正确密码也拒绝
- 会话空闲 31 分钟 → 跳登录页
- 改权重后旧版本权重未被改写、状态置 ARCHIVED；恢复 85/8/7 后榜单正常、CSV 导出正常
- 学生访问导出口 / 管理页 → 403；绩点折算 92.40、同分并列 1/1/3 等引擎回归项全部通过

## 六、给测试同学的两个提醒

1. 旧版 `test_mvp.py` 里所有 POST 都没带 CSRF 令牌，直接重跑会在第一步登录时拿到 400。正确姿势：先 `GET /login`，从 HTML 里取 `name="csrf_token"` 的值，再随表单提交；每个页面渲染出的令牌都属于当前会话。
2. 测「错误密码」用例时注意 5 次锁定；用完执行
   `UPDATE sys_user SET failed_attempts = 0, locked_until = NULL;` 复位，否则后续用例会连续 429。
