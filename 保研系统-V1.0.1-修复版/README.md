## 核心：评分引擎

`scoring.py` 是整个系统的心脏，公式写在 PRD 8.1：

```
综合成绩 = 绩点折算 × 绩点权重 + 竞赛折算 × 竞赛权重 + 论文折算 × 论文权重
         = (绩点 ÷ 5.0 × 100) × 85%
         + Σ(级别系数 × 团队排名系数) × 8%
         + Σ(分区基准分 × 作者系数) × 7%
```

三条设计原则，改代码前务必先读：

1. **权重和系数全部来自数据库**（`score_rule` 表），代码里没有任何魔法数字。管理员改规则，排名立刻变，不用改代码、不用重启。
2. **四舍五入用 Decimal 的 ROUND_HALF_UP**，不用 Python 内置 `round()`。内置是银行家舍入（2.5 → 2），学生拿计算器一按发现对不上，会认定系统算错了。
3. **同分并列同名次**，后续名次顺延（1、1、3），展示顺序用单项折算分做 tie-break，但不影响并列名次。

演示账号「黄俊键」的数据是精心设计的：绩点 4.62 → 92.40，竞赛国家级一等 + 省级一等 → 88.00，论文 B 类独作 → 86.00，加权得 91.60，与界面设计稿完全一致。这不是写死的数字，是真跑了一遍引擎算出来的——如果哪天引擎算错，这个页面对不上，一眼就能发现。

## 和界面设计稿的差异

1. **不依赖 CDN**：Tailwind 换成本地文件，演示现场断网也不会白屏。
2. **榜单展示范围**：设计稿展示带脱敏姓名的完整榜单，PRD 8.1 写的是「学生仅见本人名次与总人数」。目前按**设计稿**实现（更好演示，也符合 A-12 公示榜）。这一点需要你和产品同学确认口径——如果要改成严格口径，只需删掉 `student/ranking.html` 里表格的其他行。
3. **导航文案**：「材料填报」在原稿里是禁用态，本版已开放（V1.0 核心功能）。

## 安全说明

- 密码用 PBKDF2 哈希存储，数据库里看不到明文。
- 学生只能改自己的数据：所有增删改都会校验 `student_id` 归属，越权直接 404。
- 权限按角色拦截，学生访问管理页返回 403。
- 所有 POST 表单带 CSRF 令牌（会话级，缺失或不匹配返回 400）。
- 登录连续 5 次密码错误锁定 30 分钟；会话 30 分钟无操作自动失效；改密须 ≥8 位且含字母与数字。
- 首次登录强制改密：`sys_user.must_change_pwd = 1` 的账号登录后只能进改密页。演示账号在 `seed.py` 里标为 `0`（视为已改密），想演示该流程执行
  `UPDATE sys_user SET must_change_pwd = 1 WHERE username = 'T2001';` 后重新登录。
- `SECRET_KEY` 优先取环境变量，未设置时自动生成并保存到 `instance/secret_key`；`debug` 默认关闭，调试时设 `FLASK_DEBUG=1`。
- 生产部署前仍必须：把 `SECRET_KEY` 换成环境变量、换成 MySQL 或 PostgreSQL、加 HTTPS（见 `HANDOFF.md` 第九节）。

## 常见问题

**页面样式乱了？** 确认 `static/js/tailwind.js` 存在。这个文件是本地 Tailwind，缺了会只剩基础样式。

**登录提示账号密码不正确？** 先确认跑过 `python seed.py`，数据库在 `instance/baoyan.db`。连续输错 5 次会锁 30 分钟，可执行
`UPDATE sys_user SET failed_attempts = 0, locked_until = NULL;` 解锁。

**提交表单返回 400「表单已过期」？** 说明 CSRF 令牌缺失或会话已过期，刷新页面重新提交即可；用脚本调接口时要先 `GET` 页面拿到 `csrf_token` 再带入表单。

**改了代码没生效？** `debug` 现在默认关闭（`FLASK_DEBUG=1` 可开启自动重载）；用 `run.bat` 启动的按 Ctrl+C 再重开。
